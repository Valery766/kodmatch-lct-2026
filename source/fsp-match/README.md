# КОД.МЭТЧ – локальный запуск и проверка

Исходники соответствуют опубликованному релизу `20261011T104017Z` (версия 0.1.0). Сервис поддерживает две роли, три специализации и два уровня квалификации, объяснимый подбор, приглашения с зарплатной вилкой, раскрытие контактов по согласию, вакансии и короткие задания.

Действующий сайт: https://fsp.digital-projects.tech. Команда проверила основные пользовательские сценарии, получение писем и работу MAX на реальных подтвержденных аккаунтах.

## Локальный экземпляр: Docker Compose и Mailpit

Нужны Python 3.12, Docker Engine и Docker Compose v2. Выполняйте команды из `source/fsp-match`. При первой сборке требуется интернет для получения образов и зависимостей. Основной сценарий работает без установки языковой модели.

1. В отдельной рабочей копии выполните `python3 scripts/init_runtime.py`. Скрипт создаст `.secrets/runtime.env` и `.secrets/integrations.env` с правами `0600`, сохраняя существующие файлы.
2. В `.secrets/runtime.env` задайте собственные имена ресурсов и свободные порты:

```dotenv
FSP_COMPOSE_PROJECT=kodmatch-jury-local
FSP_NETWORK_NAME=kodmatch-jury-local-private
FSP_VOLUME_NAME=kodmatch-jury-local-postgres
FSP_PORT=18094
FSP_MAILPIT_PORT=18025
SEED_DEMO=false
```

3. В `.secrets/integrations.env` укажите данные локального экземпляра:

```dotenv
LEGAL_OPERATOR_NAME=Локальная проверка прототипа
LEGAL_OPERATOR_CONTACT=demo@example.org
```

Этот режим предназначен для тестовых данных. Внешние токены оставьте пустыми: `compose.dev.yaml` направляет письма в локальный Mailpit. Для собственного публичного размещения используются действительные данные оператора и отдельные защищенные настройки SMTP/MAX.

4. Проверьте конфигурацию и запустите приложение:

```bash
docker compose --env-file .secrets/runtime.env --env-file .secrets/integrations.env -f compose.yaml -f compose.dev.yaml config --quiet
docker compose --env-file .secrets/runtime.env --env-file .secrets/integrations.env -f compose.yaml -f compose.dev.yaml up -d --build --wait
```

5. Откройте `http://localhost:18094`; почтовый интерфейс – `http://localhost:18025`. Создайте аккаунты кандидата и работодателя. Откройте ссылку из письма в Mailpit и подтвердите адрес на странице приложения. При изменении `FSP_PORT` ссылка использует выбранный порт.
6. Кандидат сохраняет профиль и анкету, проходит тест и включает видимость. Работодатель сохраняет компанию и потребность с зарплатной вилкой, получает подборку и направляет приглашение. После принятия приглашения контакты доступны компании, которая его отправила. Удобнее использовать отдельные профили браузера для двух ролей.

На попытку отводится 45 минут; повтор той же категории доступен через 90 дней. Другая категория остается доступной. Для нового полного прогона создайте новые тестовые аккаунты.

Готовые демонстрационные профили создаются при `SEED_DEMO=true` до первого запуска и отдельном `DEMO_PASSWORD` длиной от 12 символов. Повторный запуск начальных данных сохраняет существующие изменения и историю.

Для остановки собственного экземпляра используйте ту же команду Compose с `stop`: данные сохранятся. На общей машине создавайте отдельные имена ресурсов и выбирайте порты после проверки их занятости.

## Запуск без Docker

Нужны Python 3.12 и Node.js 22. Создайте `.venv` в `fsp-match`, установите `backend/requirements.lock`, затем выполните `npm ci` из `frontend`. Команды `scripts/run_local.py api` и `scripts/run_local.py worker` используют отдельную SQLite и локальный SMTP `127.0.0.1:1025`; для почты запустите Mailpit. Команда `npm run dev` открывает клиент на `localhost:5173` с перенаправлением API на порт `8100`.

## Автоматические проверки

Из `source/fsp-match`:

```bash
PYTHONPATH=backend .venv/bin/python -m pytest backend/tests -q
node --test frontend/tests/navigation-assessment.test.mjs
```

Проверки параллельных операций PostgreSQL выполняются с `FSP_TEST_DATABASE_URL`, указывающим на отдельную тестовую базу; каждая проверка использует собственную случайную схему. Для воспроизводимой оценки алгоритмов из `source` запустите `python research/jury-validation-20261007/run_validation.py`. Скрипт обновляет только собственный JSON-отчет в рабочей копии. Все необходимые наборы данных входят в комплект.

## Размещение и языковая модель

Публичный экземпляр использует HTTPS, PostgreSQL, внешнюю почту и бота MAX. Секреты подключения хранятся отдельно от исходного кода.

Qwen3 4B Instruct 2507 Q4_K_M работает через Ollama в приватной сети. `config/compose.local-llm.yaml` подключает отдельно установленную модель и сеть; для локального запуска с Mailpit этот файл не требуется. Размещенная конфигурация допускает один запрос к модели одновременно и ограничивает ожидание 35 секундами. При недоступности модели приложение продолжает работу с детерминированными правилами.

`LLM_PERSONAL_DATA_ALLOWED=false`: резюме обрабатывается локально, контакты и исходный профиль в модель не передаются. Квалификация определяется результатом теста; решение о раскрытии контактов принимает кандидат.
