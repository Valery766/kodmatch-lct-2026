# КОД.МЭТЧ – инструкция для жюри

Редакция **11.10.2026**. Команда **unecon.tech**. [Открыть сервис](https://fsp.digital-projects.tech) · [Бот MAX](https://max.ru/se14505142_1_bot) · [Поддержка](mailto:codematch@mail.ru).

Кандидат подтверждает навыки практическим тестом, компания описывает потребность и приглашает подходящего человека напрямую. Контакты открываются только своей компании после принятого приглашения или самостоятельного отклика. Публиковать вакансию для основного сценария не требуется.

## 1. Подготовка

Понадобятся кандидат и работодатель. Владелец передает доступы приватно либо проверяющий регистрирует свои адреса с подтверждением email. Откройте роли в разных браузерах или профилях браузера: обычные вкладки одного профиля разделяют cookie. Перед действием проверьте подпись роли в меню. Узкое меню открывается кнопкой сверху слева; **«Выйти»** находится внизу.

Заранее подтвержденные аккаунты подходят для бизнес-сценария, но не доказывают получение нового письма. Для нового первичного теста используйте профиль без попытки выбранной категории: повтор одной категории ограничен 90 днями, историю не сбрасывают. Результаты технической проверки не являются оценкой способностей проверявшего человека.

## 2. Основной сценарий: кандидат

1. Откройте **«Мой профиль»**. Заполните имя, заголовок, специализацию, предполагаемый уровень, навыки, город, формат работы и зарплатную вилку. Сохраните и включите видимость профессионального профиля для подбора.
2. Откройте **«Подтвердить уровень»**. Выберите Python Backend, TypeScript Frontend или Data SQL и Junior/Middle; заполните профессиональную анкету и нажмите **«Сохранить анкету»**.
3. Нажмите **«Начать тест»**, решите пять заданий и **«Завершить и получить результат»**. Python/TypeScript – анализ/патч/трасса, SQL – ограниченный read-only запрос. Варианты строятся сервером, ответы и скрытые данные не приходят в публичную форму.
4. Проверьте баллы, компетенции, решение и **«Ваши попытки»**. Junior требует ≥65/100, Middle ≥75/100 и ≥50% каждой измеренной компетенции. Только успешный первичный тест присваивает подтвержденную категорию.
5. В **«Мой профиль»** проверьте категорию и скачайте **«Профиль в PDF»**. Обновление страницы активного теста сохраняет серверный срок; черновик восстанавливается в той же браузерной сессии. Другое устройство/полный restart не гарантирует сохранение локальных ответов.

На тест дается 45 минут; это максимальное окно, а не измеренная средняя длительность. Неудачный Middle не понижает подтвержденный Junior. Стаж, достижения и LLM не заменяют тест.

## 3. Основной сценарий: работодатель

1. В **«Компания»** заполните название, описание, направление и способ связи, сохраните. Анкета компании не означает независимую юридическую проверку.
2. Откройте **«Подбор кандидатов»** → **«Новая потребность»**. Выберите ту же специализацию/уровень, обязательные и желательные навыки, формат/город и RUB-вилку от–до за месяц до вычета НДФЛ. Согласуйте условия с профилем кандидата.
3. Нажмите **«Сохранить и подобрать»**. Сверьте категорию, индекс и **«Почему в подборе»**. На строгих условиях пустая выдача допустима; неподходящий профиль не должен попадать в нее ради числа результатов.
4. Откройте **«Профиль»**, скачайте PDF. До разрешенного события контакты кандидата скрыты и в интерфейсе, и в PDF. Добавьте закладку, проверьте **«Короткий список»**.
5. Создайте адресное приглашение с сообщением, способом связи и RUB-вилкой. Проверьте его в **«Приглашения»**. Вакансия необязательна.

## 4. Решение кандидата и проверка контактов

1. У кандидата откройте **«Приглашения»**: видны компания, задача, условия и вилка. Просмотр сам по себе не открывает контакты.
2. Примите приглашение. В работодателе проверьте статус и новые JSON/PDF-проекции: контакты теперь доступны только этой компании.
3. У кандидата в настройках отзовите разрешение компании. Повторная загрузка профиля/PDF снова должна скрыть контакты. Сохраненную ранее законную внешнюю копию невозможно отозвать задним числом.
4. Для отказа используйте отдельное сочетание кандидат + потребность. **«Отклонить»** не открывает контакты; противоречащий повтор терминального решения не меняет историю. По возможности вторая компания смотрит тот же профиль без своих контактов.

## 5. Проверка LLM и MAX

**LLM:** в новой потребности нажмите **«Помочь разобрать свободное описание»** и введите описание Python Junior API, Python/SQL, удаленно, 80–120 тыс. рублей. **«Разобрать описание»** предлагает редактируемые поля; **«Перенести поля и проверить»** требует их проверки, затем отдельного сохранения. В найденном профиле **«Пояснить подбор»** дает факты и пробелы. Индекс/порядок и категория до/после не меняются. Признаки `AI-разбор`/`AI-пояснение по фактам` означают принятый вызов; локальный fallback и кэш подписаны отдельно.

Qwen3 4B Instruct 2507 Q4_K_M работает локально через Ollama. Один inference одновременно, deadline 35 секунд, 20 AI-действий в час на работодателя. Ошибка модели не останавливает обычный подбор. Резюме/контакты/ответы теста не отправляются модели; свободный текст потребности не должен содержать персональные сведения.

**MAX:** подтвердите email web-аккаунта → **«Настройки»** → привязка MAX → одноразовая команда для бота → откройте кнопку КОД.МЭТЧ. Код и токен не публикуйте. Проверьте `/help`, `/status`, открытие кабинета, уведомление приглашения и короткой задачи. `/unlink` отменяет связь, а новый одноразовый код позволяет восстановить ее. Web-аккаунт и MAX остаются одной ролью/историей. В mini-app не должен открываться чужой кабинет. Проверка web-клиента не равна проверке всех физических iOS/Android клиентов.

## 6. Дополнительные возможности

| Сценарий | Действие | Ожидаемый результат |
|---|---|---|
| PDF-резюме | Текстовый PDF ≤5 MiB → предпросмотр → перенос → ручная проверка → сохранение | Импорт не присваивает грейд и не сохраняет исходный файл |
| Вакансия | Работодатель создает и публикует; кандидат откликается с согласием | Контакт открывается только компании вакансии; черновики скрыты |
| Короткая задача | Работодатель создает, кандидат решает, обе роли смотрят историю | Результат сохраняется, основная категория автоматически не меняется |
| Уведомления | Открыть колокольчик, отметить свое сообщение прочитанным | Статус сохраняется; ошибка транспорта не меняет контактный доступ |
| ФСП | Посмотреть источник/статус достижений; пройти сценарий без ID | Достижения – дополнительный бонус, отсутствие истории не блокирует путь |
| Мобильный кабинет | Узкое окно, открыть/закрыть меню, Escape, Tab | Основные действия доступны, фокус виден, горизонтального overflow нет |

Боевой API ФСП не предоставлен; демонстрационный adapter и введенный ID не выдаются за внешнюю верификацию. Действующая коммерческая ATS и юридическая проверка компаний не заявлены.

## 7. Почта и восстановление

Для фактической проверки регистрации используйте собственный доступный inbox: создание аккаунта → письмо → кнопка **«Подтвердить email»** → вход. Повтор письма доступен через **«Отправить письмо подтверждения еще раз»**. Ссылка 24 часа, одноразовая. **«Забыли пароль?»** → собственное письмо → новый пароль → вход; ссылка час, смена пароля завершает старые сессии.

SMTP accepted/outbox delivered означает принятие сообщения сервером отправки, а не доказанное появление в конечном inbox. Проверьте сам inbox/спам. В письмах – КОД.МЭТЧ, поддержка – [codematch@mail.ru](mailto:codematch@mail.ru). Личные пароли, mail tokens и одноразовые MAX-коды не включайте в отчет.

Технические данные после прохода восстановлены; квалификационные попытки и cooldown оставлены.

Свежий повтор на подготовленной копии исходников 11.10: **186 backend PASS /3 PostgreSQL SKIP**, **12 frontend checks**. Отдельная production-сборка опубликованного релиза сверена с JS/CSS сервера. Offline: 120 форм, 720 оценок с повтором, 180 основных пар, 78 проверок без ошибок. Это авторская синтетическая groundtruth, не независимая психометрическая оценка людей. На 6 holdout-потребностях P@5=0.3333; nDCG@5=1.0 по 5 запросам с положительной разметкой. Нельзя переводить nDCG в «100% качество найма».
